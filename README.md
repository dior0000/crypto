# ChartMate

ИИ-компаньон трейдера. Chrome-расширение распознаёт контекст графика (тикер, таймфрейм, нарисованные уровни, индикаторы), подтягивает реальные OHLCV-данные и выдаёт структурированное наблюдение с вопросами по риск-менеджменту.

**Это не сигнальный сервис.** Продукт — журнал сделок и инструмент дисциплины.

## Железное правило продукта

Система никогда не выдаёт направленный прогноз, целевые цены как рекомендацию, вероятности движения или временные прогнозы. Только объективное описание графика, вопросы по риск-менеджменту, флаги поведенческого риска и статистику по собственным сделкам пользователя. Любой ответ модели проходит через `GuardrailValidator` (`packages/shared/src/guardrails`) — если он не проходит проверку, ответ не показывается пользователю.

## Охват рынков и новости

Помимо тикера с текущего скриншота, ChartMate умеет отдавать данные по каталогу инструментов (`GET /api/market/instruments?q=`) и объективные новости по ним:

| Класс актива | Источник данных | Ключ |
|---|---|---|
| Акции NASDAQ | [Twelve Data](https://twelvedata.com) | `TWELVE_DATA_API_KEY` |
| Форекс (мажорные пары) | Twelve Data | `TWELVE_DATA_API_KEY` |
| Гособлигации США (доходности) | [FRED](https://fred.stlouisfed.org/docs/api) | `FRED_API_KEY` |
| Крипто | Binance (публичный API, без ключа) | — |

`apps/api/src/news` раз в 10 минут (`@nestjs/schedule`) забирает RSS-фиды (по умолчанию — см. `rss-feeds.ts`, переопределяется через `NEWS_RSS_FEEDS`), тегирует заметки по инструментам из каталога и хранит их в `NewsArticle`. В контекст LLM для `AnalysisService` попадает только факт публикации (источник, заголовок, время) — без summary и без интерпретации того, как новость повлияет на цену: это прямое расширение того же `GuardrailValidator`-периметра, а не отдельный источник прогнозов.

Без реальных ключей Twelve Data/FRED эндпоинты для этих классов активов возвращают ошибку `MARKET_DATA_UNAVAILABLE` — крипто и новостной инжест работают и без них.

## Локальный запуск

Нужны Node.js ≥ 20, pnpm, Docker.

```sh
pnpm install

# Postgres + Redis
docker compose up -d

# apps/api/.env — на основе .env.example; минимум задать ANTHROPIC_API_KEY,
# остальные значения по умолчанию уже указывают на docker-compose (порты 5433/6380)
cp apps/api/.env.example apps/api/.env

# применить схему БД
pnpm --filter @chartmate/api exec prisma migrate dev

# поднять всё разом (api :3001, web :5175, extension — сборка в watch-режиме)
pnpm dev
```

Для расширения: `apps/extension/dist` после `pnpm --filter @chartmate/extension run build` (или `dev`) загружается в Chrome через `chrome://extensions` → «Загрузить распакованное расширение».

### Прочие команды

```sh
pnpm build       # сборка всех пакетов
pnpm typecheck   # проверка типов
pnpm lint        # ESLint по всему монорепо
pnpm test        # тесты (guardrail-валидатор, детекторы поведенческого риска)
```

## Приватность

- Скриншот вкладки — чувствительные данные. Кадры **не хранятся** по умолчанию: анализируются и удаляются, в базе остаётся только perceptual hash (pHash) кадра и извлечённый структурированный JSON (тикер, таймфрейм, уровни, индикаторы).
- Расширение запрашивает разрешение `activeTab`, а не доступ ко всем сайтам (`<all_urls>`).
- Захват экрана происходит только пока сессия явно активна — в side panel в это время виден индикатор записи.
- Все обращения к LLM идут только через бэкенд; ключи API никогда не попадают в расширение.
